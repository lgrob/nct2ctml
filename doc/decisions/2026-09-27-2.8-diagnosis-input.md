# Diagnosis input: labelled sections and an exclusion rule (roadmap 2.8)

- **Date:** 2026-09-27
- **Roadmap:** 2.8
- **Outcome:** adopted: DIAGNOSIS_INPUT = labelled
- Moved from CHANGES.md on 2026-09-28 (improvement plan step 13); the text is unchanged.

The diagnosis step was given the exclusion criteria alongside the inclusion
criteria. For CTIS they were joined with the conditions and no labels at
all. In the full run it returned diagnoses named only in the exclusion
criteria as eligible ones: 113 of them in 75 trials. config.DIAGNOSIS_INPUT
selects the text for the ClinicalTrials.gov global and arm-level calls and
for CTIS. The default is now `labelled`: both registries get labelled
sections, and the prompt says excluded conditions are not to be returned
unless the inclusion criteria, title or conditions also name them.

Measured with Haiku 4.5 on 123 trials (the 56-trial answer key plus the 67
trials flagged diagnosis_excluded), 3 replicates per mode. Only diagnosis
calls were new; every other answer came from the full run.

| | legacy | labelled | inclusion_only |
|---|---|---|---|
| exclusion-only diagnoses (123 trials) | 113 | 57 | 24 |
| CTIS / NCT | 29 / 84 | 12 / 45 | 4 / 20 |
| key population recall | 0.933 | 0.940 | 0.905 |
| key population precision | 0.808 | 0.818 | 0.894 |
| key name F1 | 0.736 | 0.752 | 0.810 |

Differences from legacy, trial-paired: labelled recall +0.007 [-0.002,
+0.020], name F1 +0.016 [0.003, 0.031]. Labelled loses one curated
diagnosis in all 3 replicates: Ewing Sarcoma on NCT03838042, which the text
does not name and legacy found in 2 of 3. inclusion_only loses 16 curated
diagnoses in 9 trials (medulloblastoma, GBM IDH-wildtype, pilocytic
astrocytoma, three rhabdomyosarcoma subtypes, and others), so recall-first
rejects it. The remaining exclusion-only diagnoses are still caught by the
diagnosis_excluded flag. The switch takes effect at the next map run.
