### Against the replayed Haiku answers of 2026-10-01

The same three trials in the replay at `412f46c` (artifact
`haiku_412f46c_report.json`):

- **No patient is lost.** Population recall is equal or higher on every
  trial. NCT02332668 went from 0.75 to 0.86.
- **Each difference is an extra diagnosis.** NCT01704716 has 2 against 1,
  NCT02332668 10 against 3, and NCT02393157 8 against 7. Gene and age F1 are
  identical on all three.
- **The likely cause is the code, not the API.** About twenty commits
  separate `412f46c` and `d84963b`. Among them is the diagnosis text floor
  (`f3181b8`, widened in `8ed3a9e`), which only ever adds diagnoses.
- **Three trials cannot separate that from run-to-run variation.** Haiku at
  temperature 0 differed between two of its own runs on 6 of 50 trials.
- **NCT02332668's 10 diagnoses** are flagged `dx over-generated` by the
  scorer but stay under the `diagnosis_over_generated` routing threshold,
  so the trial was published.
- **NCT01704716 scores gene F1 0.00 in both runs.** The key requires MYCN,
  and neither run returned a gene. That is a known extraction gap, not an
  API effect.

## Defects found

1. **The API key was not scoped to a workspace.** The first job (Slurm
   7369655) failed at the preflight with `400 invalid_request_error: This API
   key is not scoped to a workspace`. A key created inside a workspace in
   the Anthropic Console fixed it, with no code change. The other fix, an
   `anthropic-workspace-id` header, was not needed. The preflight caught the
   error with one call, before any mapping.
2. **The first version of the smoke mode** called `main.py map --nct_id`
   three times. That wrote three run records, of which the summary read
   only the last; it wrote output to the node-local `/tmp`; and it would
   have sent a review-routed trial into the curators' queue. Fixed in
   `d84963b` before this run: the smoke test now goes through
   `bench.benchmark_map`, and the summary covers every run the job created.
